# OW Ban Pick UI 场景规范

本目录将已确认的房间 UI 产品规则表达为结构化场景。`status.yaml` 继续只描述后端权威状态；这里描述相同状态在四种入口中应如何显示和操作。

入口文件是 `manifest.yaml`。阅读顺序：

1. `ontology.yaml`：角色、图层、前景页面、控件和状态枚举。
2. `fixtures.yaml`：场景复用的最小权威状态、运行时状态、配置和本地 UI 默认值。
3. `baseboards.yaml`：比赛底板在各生命周期中的稳定表现。
4. `notifications.yaml`：服务器权威通知事件、统一无色调文案、受众和持续方式。
5. `global-admin.yaml`：全局管理员页面的网站设置、模板配置、条件禁用、目录维护、房间和历史管理规则。
6. `scenarios/*.yaml`：按比赛阶段组织的角色视图、权限、动作和转换。
7. `scenario-schema.yaml`：场景文档需要满足的结构。

每个场景都必须显式填写队伍1、队伍2、管理员和直播四个入口。`foreground` 描述看到的当前页面，`mode` 描述交互方式，`controls` 逐项描述按钮可用、禁用或隐藏，`notifications` 描述动作成功后由服务器产生并发给各入口的右上角消息。直播入口使用 `phase-readonly-mirror` 镜像当前阶段，但始终没有可用操作控件。

修改需求时应先修改或新增场景，再同步前端实现和 Playwright 验收。不要将弹窗、通知、输入草稿或角色视图规则写回 `status.yaml`。

`reviewStatus` 含义：

- `confirmed`：产品规则已经确认；当前实现如不一致，应以该规则为目标修改。
- `current-only`：当前实现存在，但产品规则尚未明确确认。
- `needs-review`：文档和实现不一致，或仍需产品决策。
- `proposed`：为了补齐状态空间提出，当前尚未完整实现。

跨多个场景的已确认规则集中记录在 `manifest.yaml` 的 `crossCuttingDecisions` 中，避免在每个阶段重复同一决策。

当前确认规则还包括：产品不支持取消比赛；比赛结束只在底板中部显示“比赛已结束”；最小化是本地辅助能力且不暂停计时；阶段回退只由房间管理员按“地图序号 + 业务阶段”操作，全局管理员页面不配置检查点。
